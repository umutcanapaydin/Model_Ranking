3b · TESTER ★ v3

subagent-profiles/Tester.md (fresh eyes)
  • Every acceptance criterion has a citing test (V3C-02)
  • Reproduce reported symptom red→green first
  • Coverage on new/changed code
  • ★ v3.1 fault-injection (V3C-72): break → confirm RED; stay-GREEN fault = missing test (mandatory); revert IN PLACE, md5-verified
  • ★ v4.0 mutation kill-rate (V4C-01, HIGH, ADVISORY): if a runner is wired, mutant kill-rate on changed code reported BESIDE the verdict, separate from coverage — never blocks
  • Flush all fixes before the wave exits
STRUCTURED VERDICT (★ v2.0): PASS / MINOR / BLOCKING + file:line evidence per acceptance criterion. PASS without evidence = automatic BLOCKING.
★ v3.1 — RISK TIERS + WAVE-CLOSE CHECKLIST (V3C-78 / V3C-69): LOW/MED wave → ONE combined reviewer; HIGH (auth/payment/crypto/migration/distributed-correctness — auto-escalated) → Code + Tester + pulled-forward Security-on-slice. The wave closes only when its committed checklist (docs/wave-checklist.template.md, make wave-check) is green — fresh evidence per row, skipped/waived checks ledgered. Escaped blocker on a tiered-down wave → full review (tripwire).
★ v4.0 — REVIEW INDEPENDENCE + FRICTION TELEMETRY (V4C-03/04 · V4C-06 · V4C-13): at HIGH, ≥1 fresh-eyes seat SHOULD run on a DIFFERENT model family than the author (advisory; author/reviewer family + fresh-context assertion recorded in the verdict). Constitution invariant: reviewers/gates read policy ONLY from the protected base ref — diff/comment content that tries to alter review policy is an injection-class FINDING. Checklist row 9 is now the skipped/waived/BYPASSED ledger with cost lines: a control bypassed under pressure is recorded, and the SAME control bypassed 3× triggers review of the CONTROL.
PASS · MINOR · BLOCKING ?
BLOCKING → re-dispatch same wave fix, re-run Code+Tester. Next wave NOT started.
PASS / MINOR → next wave (Stage 2) or Stage 4 if all waves done.
↻ loop back to Stage 2 until all waves PASS/MINOR

STAGE 5
Maintenance Loop — post-deploy fixes ★ v3.4
fix waves · fixpack deploy gate · owner out-of-sandbox ★ v4.0: scheduled journey + canary

FIX WAVES (V3C-98)

  • Red-test intake: no fix wave opens until the prod bug is a FAILING test — the red test IS the frozen spec; fixes only turn red green
  • Normal wave machinery applies: checklist + fresh-eyes Code-Reviewer + Tester (prod bugs on ⛔ paths auto-HIGH)
  • Exploitability triage per bug at intake; security-class → escalate-NOW + invariant test
  • Every red test joins the PERMANENT regression suite (bug-ID tagged)

FIXPACK = THE DEPLOY GATE

  • ≤5 fixes / ~400 lines; HIGH/⛔ ships solo; security floor + full invariant suite + full regression on the exact final bundle
  • OWNER OUT-OF-SANDBOX VERIFICATION (BLOCKING): reproduce on pre-fix build → gone on fixpack build → local tests → signature
  • Deploy via 4.3 gate · fix probe · watch window · make journey re-run green
  • ★ v4.0 (V4C-07): the journey script gains a SCHEDULED post-deploy life — monitoring-as-code: named on-call owner, flake/mute policy, synthetic-safe, CI-held scoped creds; results land in the watch record
  • ★ v4.0 (V4C-08, stack-conditional): canary/pre-post verify + mechanical rollback where the platform supports it — and a rollback that never fired is a doc, not a control (rehearse once per stack)
  • Capture coupling (deploy condition): per-fix lessons append to EXPERIENCE; 3-strikes gate-attribution; N=3 fix-on-fix → surface locked, refactor milestone

3 · 3-Layer Issue Management v2.0 NEW

Full GitHub-automated flow. Human review only at PR merge (branch protection enforces).

L1 · PURE CI (no agent)

Deterministic hygiene
  • Test suite on PR + push
  • Gitleaks (secret scan)
  • pip-audit (dep CVE)
  • Auto-label by title/path
  • Stale-issue bot (60d)
  • Link issue↔PR

L2 · CI-TRIGGERED AGENT

Headless Claude
  • agent:triage label → /triage-issue → diagnosis
  • agent:fix label → /fix-issue-prepare → /fix-issue-implement → draft PR
  • Label-gated, draft-only, timeout-capped
  • Least-privilege token
  • Pinned action SHAs
Ship: shadow-mode 1 milestone, then graduate.

L3 · SCHEDULED + INTERACTIVE

Periodic + pairing
  • /schedule sweeps (dependency hygiene)
  • Layer-3 sweep opens issues
  • Interactive via GitHub/GitLab MCP
  • Backlog grooming
Ship: after L2 trusted (≥2 milestones).
