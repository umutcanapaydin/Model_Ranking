Bootstrap — once per project (~4-8 hours)
project birth
Two paths: Path A (paste repo-starter.md into Claude Code) · Path B (cp -r starter package + fill PROJECT placeholders).
Gates:
  • AGENTS.md ≤80 target / ≤150 hard cap, PROJECT filled, UNIVERSAL untouched, CLAUDE.md → AGENTS.md symlink
  • pyproject.toml + project name + initial deps (mirror AGENTS.md per C.4)
  • permission-matrix.md adapted; OS-aware Bash / PowerShell patterns confirmed
  • subagent-profiles/Code-Reviewer.md + Security-Reviewer.md baseline in place
  • .mcp.json: GitHub or GitLab MCP server set
  • — install completeness FIRST : make install-check diffs this tree against INSTALL-MANIFEST.md. M1 a declared PROJECT path missing → FAIL · M2 a GP-INTERNAL path leaked in → FAIL. Measured on the first field run: 39 declared files missing from a project that had already closed two milestones — including the whole .agents/ house rules and .claude/ hooks, so seven AGENTS.md citations pointed at nothing and those rules were never read.
  • Day-1 green: make check — now lint typecheck test check-records install-check. the last two had targets and no caller anywhere; they are wired into make check, pre-commit and CI, unconditionally.
  • Host-side admin (one-time): branch protection on main + ANTHROPIC_API_KEY secret + 90-day rotation cal

STAGE 1
Milestone Plan — per milestone (~1 hour)
writing-plans format
Output: docs/plans/m{N}-plan.md
  • Goal + REQ-ID acceptance + wave decomposition
  • — the warning ledger : every WARN gets an id in docs/warnings.ledger.md and a wave cannot close while one is undecided. C2a a warning may not outlive its close · C2c ACCEPTED needs a reason AND an owning milestone · C2b the same control ACCEPTED 3× fails the build. Measured: one control was skipped in five consecutive wave closes, the 3× trigger never fired because nothing counted, and when that suite finally ran once it produced six engine defects no unit test could reach. A control that warns into a void has not run.
  • K.8 contract surfaces grep-verified (grep -n output pasted)

STAGE 3
Per-Wave — Code Review & Tester (fresh-eyes)
fresh-eyes K.7 · Security → closure () · risk-tiered + wave-checklist

3a · CODE REVIEW

subagent-profiles/Code-Reviewer.md via /review
  • Plan compliance
  • Integration drift
  • K.8 contract grep-verify
  • K.9 cross-wave gap spot

3b · TESTER

subagent-profiles/Tester.md (fresh eyes)
  • Every acceptance criterion has a citing test
  • Reproduce reported symptom red→green first
  • Coverage on new/changed code
  • Fault-injection: break → confirm RED; stay-GREEN fault = missing test (mandatory); revert IN PLACE, md5-verified
  • Mutation kill-rate: if a runner is wired, mutant kill-rate on changed code reported BESIDE the verdict, separate from coverage — never blocks
  • Flush all fixes before the wave exits
STRUCTURED VERDICT : PASS / MINOR / BLOCKING + file:line evidence per acceptance criterion. PASS without evidence = automatic BLOCKING.
RISK TIERS + WAVE-CLOSE CHECKLIST: LOW/MED wave → ONE combined reviewer; HIGH (auth/payment/crypto/migration/distributed-correctness — auto-escalated) → Code + Tester + pulled-forward Security-on-slice. The wave closes only when its committed checklist (docs/wave-checklist.template.md, make wave-check) is green — fresh evidence per row, skipped/waived checks ledgered. Escaped blocker on a tiered-down wave → full review (tripwire).
REVIEW INDEPENDENCE + FRICTION TELEMETRY: at HIGH, ≥1 fresh-eyes seat SHOULD run on a DIFFERENT model family than the author (advisory; author/reviewer family + fresh-context assertion recorded in the verdict). Constitution invariant: reviewers/gates read policy ONLY from the protected base ref — diff/comment content that tries to alter review policy is an injection-class FINDING. Checklist row 9 is now the skipped/waived/BYPASSED ledger with cost lines: a control bypassed under pressure is recorded, and the SAME control bypassed 3× triggers review of the CONTROL.
PASS · MINOR · BLOCKING ?
BLOCKING → re-dispatch same wave fix, re-run Code+Tester. Next wave NOT started.
PASS / MINOR → next wave (Stage 2) or Stage 4 if all waves done.
↻ loop back to Stage 2 until all waves PASS/MINOR

BLOCKING — must PASS before 4.3 deploy

  • invariant NEGATIVE tests · built≠wired live-path check · money sweep · skipped-checks ledger

4.1 · QUALITY GATE

Judgment, not mechanical
  • Done Evidence assembly
  • REQ-ID trace (coverage-by-req.md)
  • Coverage delta on new code
  • Strict mypy + ruff
  • LOC budget check
  • cost-log.md vs Stage 1 estimate
  • BLOCKING → milestone NOT closed

4.2 · CAPTURE

  • process-log.md S{N} (G.1)
  • ADRs via /log-decision skill
  • seeds proposed → user-approved → active
  • retrospect M≥3 via /retrospect (G.12) — hook fails closure if missing

  • AGENTS.md diet ≤150
  • dated docs/EXPERIENCE.md entry · retro answers+poses the carried question
  • Disciplines-retired count

4.3 · DEPLOY + GO-LIVE

only if the milestone deploys
  • curl /health | jq .build == intended tag (L.7); restart != rebuild
  • CODEOWNERS build files not clobbered (K.10)
  • make smoke-deps: invoke each dep once — configured != working (L.8)
  • read config back from the process, not the values file (L.9)
  • pipe attribution via downstream run-log (E.6)

4.4 · HANDOFF

  • note.txt refresh (always)
  • If M%3==0: /quarterly-handover → handover_q{N}.txt
  • Harness diet: retire unused hooks/skills/MCPs (90d)
  • handover BLOCKS without a fresh milestone-keyed EXPERIENCE.md entry
↓ after go-live
STAGE 5
Maintenance Loop — post-deploy fixes
fix waves · fixpack deploy gate · owner out-of-sandbox : scheduled journey + canary

FIX WAVES

  • Red-test intake: no fix wave opens until the prod bug is a FAILING test — the red test IS the frozen spec; fixes only turn red green
  • Normal wave machinery applies: checklist + fresh-eyes Code-Reviewer + Tester (prod bugs on ⛔ paths auto-HIGH)
  • Exploitability triage per bug at intake; security-class → escalate-NOW + invariant test
  • Every red test joins the PERMANENT regression suite (bug-ID tagged)

FIXPACK = THE DEPLOY GATE

  • ≤5 fixes / ~400 lines; HIGH/⛔ ships solo; security floor + full invariant suite + full regression on the exact final bundle
  • OWNER OUT-OF-SANDBOX VERIFICATION (BLOCKING): reproduce on pre-fix build → gone on fixpack build → local tests → signature
  • Deploy via 4.3 gate · fix probe · watch window · make journey re-run green
  • the journey script gains a SCHEDULED post-deploy life — monitoring-as-code: named on-call owner, flake/mute policy, synthetic-safe, CI-held scoped creds; results land in the watch record
  • canary/pre-post verify + mechanical rollback where the platform supports it — and a rollback that never fired is a doc, not a control (rehearse once per stack)
  • Capture coupling (deploy condition): per-fix lessons append to EXPERIENCE; 3-strikes gate-attribution; N=3 fix-on-fix → surface locked, refactor milestone

3 · 3-Layer Issue Management NEW

Full GitHub-automated flow. Human review only at PR merge (branch protection enforces).

L1 · PURE CI (no agent)

Deterministic hygiene
  • Test suite on PR + push
  • Gitleaks (secret scan)
  • pip-audit (dep CVE)
  • Auto-label by title/path
  • Stale-issue bot (60d)
  • Link issue↔PR
Ship: day-1.

L2 · CI-TRIGGERED AGENT

Headless Claude
  • agent:triage label → /triage-issue → diagnosis
  • agent:fix label → /fix-issue-prepare → /fix-issue-implement → draft PR
  • Label-gated, draft-only, timeout-capped
  • Least-privilege token
  • Pinned action SHAs
Ship: shadow-mode 1 milestone, then graduate.

L3 · SCHEDULED + INTERACTIVE

Periodic + pairing
  • /schedule sweeps (dependency hygiene)
  • Layer-3 sweep opens issues
  • Interactive via GitHub/GitLab MCP
  • Backlog grooming
Ship: after L2 trusted (≥2 milestones).
