# M12 inputs — the first requirements this project has ever had from a real user

> **Not a plan. The raw material for one**, written the day it arrived so it cannot be remembered
> selectively later. M11 closes first, by the owner's ruling.

## Where these came from, and why that matters more than any single item

The owner gave the app to other people, and one of them is a **60-year-old CFO**. His words for
the goal: *"our aim is to let this man, who is as far from the AI world as it gets, understand
these and choose for himself"* (owner, translated from Turkish).

Eleven milestones of this product were specified by the people who built it. Every requirement in
`docs/prd.md` before this record was written by someone who already knew what a benchmark was.
**Four of the five items below are the same defect wearing different clothes: the product explains
what it measured in the language of the measurement.** That is not a wording problem, it is a
whole-product finding, and it arrived the moment somebody outside the room used it.

## The five, as reported

### 1. Turkish, with a flag switch in the top-right

**Decided 2026-08-23 by the owner: the ENGINE returns structured facts and the CLIENT composes the
sentence.** This is a contract move and needs its own ADR.

Measured before the decision, because the obvious reading was wrong: this is not a string file.
Every sentence on screen is generated by the engine, in English — `title`, `pick.why`,
`trade_off`, `ordering_note`, `stale_notice`, `effort_mix_notice`, `close_call`,
`unavailable_reason`. Localising by translating them client-side would be machine-translating
sentences that carry numbers, which is how a product starts lying in a second language.

The rejected alternative was `?lang=tr` on `/v1`: smaller, and it writes every future sentence
twice and pays the whole cost again on the third language. **Prose in an API is a localisation trap
and the trap was already sprung; the question was only whether to notice.**

### 2. A link to each tool's official site — "Go to Page"

**Needs data this project does not have.** The payload carries `evidence_source_url`, which is the
BENCHMARK's source, not the vendor's product page. A model→URL map has to be curated, and being
wrong here sends a reader to the wrong company. Scope it as a source, not as a button.

### 3. Simpler category names

The owner asked for suggestions. Proposed, each derived from what the surface actually measures:

| Now | What it measures | Proposed |
|---|---|---|
| Coding | fixes real GitHub issues | Coding *(keep)* |
| Agentic coding | works a repository unattended | Coding on its own |
| Everyday assistant / chat | human side-by-side preference | Chat |
| Everyday questions | broad capability index | General knowledge |
| Expert reasoning | PhD-level science questions | Hard science questions |
| Mathematics | competition mathematics | Mathematics *(keep)* |
| Computer use | drives a terminal unattended | Operating a computer |
| Abstract reasoning | unseen visual puzzles | Puzzles & pattern finding |
| Web development | builds web pages | Web development *(keep)* |

**Found while writing this table:** two of the nine begin with "Everyday" — `assistant` is
"Everyday assistant / chat" and `everyday` is "Everyday questions". The owner mixed them up on his
own screen during the M11-W3.5 session and so did the lead agent while reading his screenshots.

### 4. "$1.03/1M" means nothing to a CFO

1M tokens is roughly 750,000 words, roughly **1,500 pages**. The number stays exact and gains a
plain line beside it: *"about $1 for 1,500 pages of text"*. A CFO thinks in cost per unit of work;
"per million tokens" is a unit only this industry uses.

### 5. `161.7 ECI` and `1504 elo` mean nothing; `83.5 % resolved` is fine

The percentages already read as English. The index and the rating do not, and no amount of
rewording fixes a number whose scale nobody knows.

Proposed: show the RANK beside the raw score — `#3 of 21` — plus one sentence saying what the
number is. Rank needs no scale to be understood. It comes from the engine's own ordering, so the
client is reading a position rather than computing one, and Trap 1 stays intact.

## What this record is NOT

Not a commitment to all five, not an ordering, and not a plan. M12 gets planned and signed the
normal way. This exists so that when it is planned, it is planned against what was actually said
rather than against what was still remembered.
