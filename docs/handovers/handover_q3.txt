=======================================================================
1. THE PRODUCT IN SIX LINES
=======================================================================
It answers "which AI tool should I use, at my budget" from public measurements, deterministically,
with no LLM anywhere in the scoring path (D-104). Nine categories, each ranked on ONE benchmark on
its own native scale — Elo and percentages are never averaged (D-105). Three picks per surface:
best quality, best value, budget pick. Every answer carries what it is unsure about: near-ties,
stale evidence, undated evidence, a surface with no evidence at all. The engine serves it over
`/v1`; a SwiftUI app reads it; a refresh keeps it current. **Its whole claim is that it tells you
what is true right now, and everything above exists to keep that sentence honest.**

3. WHAT THREE QUARTERS OF FIELD USE HAVE ACTUALLY TAUGHT
=======================================================================
These are ranked by how often they recurred, not by how interesting they are.

(a) ALMOST NOTHING IS FOUND BY READING. Across M7-M9, essentially every serious defect was found by
    fault injection or by a seat that had not written the code. The measured version: at M9 an
    independent reviewer wrote 40 mutants against a module whose author had written 24 and reported
    all killed; 8 survived. **A mutant set written by the author tests the author's model of the
    code.** If you do one thing from this file, get someone else to write the mutants.

(b) A CONTROL WHOSE SCOPE IS NARROWER THAN THE RULE IT CITES IS NOT A GATE. This is the newest
    named class and the most productive. It runs, it fails on some inputs, and it reads as a gate in
    every record. Diagnostic question: name the population this control examines, then name the
    population the rule covers — are they the same set?

(c) A TEST CANNOT FAIL IF ITS FIXTURE CANNOT REACH WHAT IT ASSERTS. Six instances across M8-M9. A
    surface with three models cannot express "loses more than a quarter"; a fixture with no
    secondary-benchmark rows cannot express a secondary-score change. Both read identically to
    tests that work.

(d) AN ENUMERATION THAT IS TYPED OUT IS A DENYLIST WEARING BETTER CLOTHES. Still true, still
    recurring. M9's version was a hand-written list of six hashed fields where the payload published
    ten — and the four missing ones made the refresh unable to publish a freshness update at all.
    **Derive the set; name the exclusions.**

(e) A SEAM IS ONLY A SEAM IF IT REACHES THE CALLER. Four instances now. The fourth was written into
    the module whose own docstring claimed the parameter was read at call time.

(f) RESTART IS NOT REBUILD, AND THE BUILD STAMP IS THE ONLY WITNESS. Twice.

(g) REPRODUCING A FAILURE PROVES IT IS REAL AND PROVES NOTHING ABOUT ITS SCOPE. A dependency was
    written off for a milestone on one endpoint's word; asking the dataset directly took four
    commands.

(h) THE FAILURE THAT LOOKS LIKE SUCCESS IS THE ONE TO DESIGN AGAINST. An unattended process that
    FREEZES is worse than one that publishes something bad, because a freeze is invisible: every
    gate green, every cycle exiting 0, the artifact quietly ageing.

4. THE THING A NEW READER MOST NEEDS TO KNOW
=======================================================================
**There is one machine, and several of this project's load-bearing separations are claims about a
topology that does not exist.**

D-116 says ingestion never runs on the serving host. M9 wrote REQ-REF-007 to enforce it and could
not: the owner's Mac is the serving host and the only host. The structural half is real — the
refresh imports nothing from the adapter, and a test walks the AST to prove it — but the physical
half has never been tested, because there is nowhere else for it to run.

W-030 and W-031 have said a version of this about the platform surface for three milestones. It is
the same sentence, arriving from inside the product rather than from a deploy checklist:

    A separation you cannot violate because you only have one machine is not a
    separation you have verified.

Nothing is on Fly.io. Nothing is billing. The engine is deploy-ready and has been since M7.

=======================================================================
5. HOW TO WORK HERE
=======================================================================
- `./runner` first, always. If it is not all-PASS, stop and read `latest.log` before anything else.
- The owner runs the milestone tests and makes the milestone commits. Agents commit at wave
  boundaries under D-117, never as the owner (V4C-64), and never on a red gate — a rule broken
  three times in this project, each time by reading the exit code after the commit.
- Every criterion needs a citing test PROVEN RED. "A test exists" is not the bar and never was.
- Escalate immediately, without waiting for a boundary: a suspected secret, a security finding, a
  scanner suppression, or a scope change that invalidates the plan. M8 stopped mid-change to ask
  before rewriting a security finding's citing test, and that was the correct call.
- Records are append-only. When a record is wrong, correct it and NAME the error — do not rewrite
  it into having been right. M9 did this twice and both corrections carry more information than the
  original text did.

=======================================================================
7. THE QUESTION THIS QUARTER LEAVES
=======================================================================
The refresh removes the last human from the loop, and the human was the error-detection mechanism
for everything the gates do not cover. A build that "fails loud" is loud to somebody reading.

    What does this system do when it is wrong and nobody is looking?

Not "when a source is down" — that is designed for, disclosed, and tested. The question is what
happens to a defect no gate catches, in a product that now updates itself, when the person who used
to notice is no longer in the path. M9 added a status file and an escalation counter. That may be
the answer, or it may be the smallest thing that let the milestone close. **M10 should find out
which, before adding anything else.**
