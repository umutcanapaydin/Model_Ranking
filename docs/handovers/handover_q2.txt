1. THE PRODUCT IN SIX LINES
=======================================================================
It answers one question honestly: "which AI subscription or model should I buy?"
- A curated plan table (data/plans.yaml) plus provider rosters link a PLAN to the MODELS its
  provider explicitly names.
- Free-and-legal benchmark and pricing sources score those models.
- A deterministic, rule-based engine — no LLM anywhere in the data or scoring path (D-104) —
  returns labeled answers per task category and budget.
- The product's value is the honesty of the links, not the ranking math.
- Since M6 it serves that over a read-only HTTP surface; the iOS advisor app is the consumer.
- Everything user-facing is ENGLISH since D-118, including the query vocabulary.

2. THE DOCTRINE YOU MUST NOT BREAK
=======================================================================
Everything in handover_rocky.txt §2 still holds. Unchanged and still paid for:
- A score is a (model, harness, EFFORT) triple. Never average across scales, never mix benchmarks
  within a category (D-105).
- Never invent a price or a score. Unmatched names are DROPPED and COUNTED.
- Fail loud, fail closed, per source. A health check fails toward DISCLOSURE — and M6 measured what
  the other direction costs: the API's first staleness signal could not fire for a server process,
  and it took a security seat to notice the answer had gone quiet rather than fresh.
- Only documented endpoints. Artificial Analysis is BANNED (D-101).
- D-112: a category with no effort policy DISCLOSES an unequal comparison rather than shrinking the
  board. Do not re-litigate.

ADDED BY M6, and each of these is now a contract:
- **D-115 — both coding answers, neither leading.** No `primary` flag, no semantic ordering, no
  top-level winner, under ANY spelling. The payload's key set is frozen by a test because two
  weaker formulations were walked past.
- **D-118 — one language, at the source.** Translating at the API boundary would give one run two
  texts. If a Turkish surface is wanted, it is a localization layer over message keys, not literals.
- **D-116 — the deploy target and its condition.** The evidence database is a shipped artifact; the
  serving host runs no ingestion, so the code that talks to third parties never runs where the
  public can reach it.
- **D-120 — `schema migrate` exit 3.** "Migrated, and not yet usable." A migration can add a
  column; it cannot supply a policy.

3. THE METHODOLOGY
=======================================================================
Framework: General Pipeline **v5.0** (D-113, adopted mid-M6, superseding v4.3.1). Installed with
v5.0's own `make export-project`, never by copying the package.

Operating mode A0.5. **Git authority changed twice in one day and the current state is D-117:** the
lead agent MAY commit and push at WAVE boundaries under five conditions — its own identity, GP-Agent
and GP-Task trailers, green gates only, no catastrophe-class operations, and the milestone-closing
commit stays the owner's. D-114 had removed that authority entirely; D-117 returned a narrower form.
Read both before assuming either.

Stage shape per milestone: Plan (owner signs) -> Waves 1..4 -> per-wave fresh-eyes review -> closure.
Cap ~4-6 waves / ~2k net lines. Close early.

**V3C-78 risk tiers, and M6 is the evidence they are not ceremony.** W3 carried a schema migration,
so it auto-escalated to HIGH: a separate Code-Reviewer AND Tester plus a pulled-forward security
pass. That produced 4+3+2 BLOCKING. The Tester alone ran 52 mutants across three rounds against the
author's 11, and 16 stayed green. One combined reviewer would have shipped an unwired startup
validator, an unguarded network-fed YAML input, a broken CLI exit-code contract, and a denial of
service the author introduced while fixing a denial of service.

v5.0 adds the **wave footprint** block (Touched / K.8 contracts / Closure rounds), required by
`make wave-check`. This project also records, beyond the template, which gate each wave stalled at
and for how long — the owner asked for it and the three lines do not carry it.

=======================================================================
9. THE LESSONS THIS PROJECT HAS PAID FOR
=======================================================================
docs/EXPERIENCE.md has the full set, dated. The five that keep recurring:

- A guard that cannot fail is worse than no guard, because it reads like coverage. Write the mutant
  that should kill it in the same sitting.
- **An enumeration that is typed out is a denylist wearing better clothes.** M6 found this four
  times in one milestone — a precedence guard, a YAML wiring predicate, a list of YAML inputs, and a
  set of smoke-test endpoints. Every one was missing exactly the member that mattered. When you
  write a list of things to check, write the code that produces the list.
- **Reachability, not logic, is where this project's tests are weakest.** A test of a function
  nobody calls passes exactly as well as a test of one that ships.
- A new SOURCE is a new corpus. Extend the registry's live-name expectations in the same commit.
- A fix inherits the risk class of the bug it fixes. M6's proof: the cycle guard added to close a
  denial of service introduced one, and only running the guard twice in one process could find it.

And one about the process rather than the code:
- **A control whose only remedy requires the owner will survive every close until someone asks him
  for a decision instead of showing him a status.** W-001 survived four closes and took one message
  to fix.

Good luck. The repository is honest right now — that is its most valuable property and it is easier
to lose than to build.
