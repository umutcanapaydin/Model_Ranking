# Two agent tools on one repository

Read this file only while a second agent tool (Codex, or another) works in this repository beside Claude Code. Every rule in `AGENTS.md` binds both tools; only the tooling differs:
- **Shared:** `AGENTS.md` §3's branch and draft-PR rules — one issue, one agent, one branch: claim the issue with a comment (`claimed by codex on fix/issue-12-login`), never commit on a branch the other tool opened, parallel work in separate worktrees, never two tools in one checkout; no AI attribution. A skill is a file — `/fix-issue` means `.claude/skills/fix-issue/SKILL.md`: the second tool opens it and follows it. A reviewer profile (`.claude/agents/`) runs as a separate session of either tool, and the other tool is a valid fresh reviewer (K.7).
- **One process log.** `docs/process-log.md` entries are headed by date and branch, never a running number, so two tools append without colliding; name the tool in the entry's `**Agent:**` line. (Older `## S<n>` headings stay as they are; `check_records.py` still refuses one number used twice.)
- **What the second tool cannot leave:** no dispatch record and no transcript. Its review verdicts therefore carry no dispatch, and the human who merges the PR records the verdict — its `**Independent:** yes` is that human's reading, not the gate's. The hooks in `.claude/settings.json` run only under Claude Code: the second tool runs `make check-fast` after each edit itself and never runs what `AGENTS.md` §5 forbids.
- **Codex runs the Bash guard** from `.codex/hooks.json`, the same pinned command, once the project is trusted. It trusts a hook by its hash, so after every `make guard-pin` it skips the guard until you trust the changed hook again in `/hooks`.
